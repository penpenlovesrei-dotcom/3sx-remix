  `C:\msys64\mingw64\bin\`. **Ne pas risquer de mise à jour partielle** (`pacman -Sy` seul) :
  elle y a déjà cassé des `.exe`.
* **Python 3, avec `numpy` et `Pillow`.** Si `python` sort sans rien dire, c'est le
  bouchon du Microsoft Store : utiliser `py -3` ou le chemin complet.
* **Reconfigurer** — le `build\` copié n'a plus ses fichiers CMake :

  ```
  cd C:\Temp3sx\build
  cmake -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++ ..
  cmake --build .
  ```

  C'est la configuration relevée dans le `CMakeCache.txt` de l'ancienne machine :
  Ninja, Release, `clang` / `clang++` de `C:\msys64\mingw64\bin\`.

  Ne **jamais** filtrer la sortie de compilation, et **tester le code de sortie** : le
  silence n'est pas un succès. Puis recopier `build\3sx.exe` dans
  `build\application\bin\` — c'est **toujours** celui-là qu'on lance, l'autre n'a pas ses
  DLL. L'exe se verrouille quand le jeu tourne.
* **Comparer** le `3sx.exe` fraîchement compilé avec `build\3sx.exe` copié (06/09) : la
  même source sur un autre compilateur peut différer d'octets, mais si la taille s'écarte
